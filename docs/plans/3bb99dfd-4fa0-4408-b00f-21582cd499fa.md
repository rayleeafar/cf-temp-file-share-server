## Goal

Redesign the entire frontend to a dark tech-style UI, add a token-authenticated file-update API endpoint, generate Swagger/OpenAPI documentation, and write a full README.md for the project.

## Context

- Existing Cloudflare Pages + R2 application with POST upload, GET download, and GET file-listing endpoints.
- Frontend (`public/`) is a light-themed minimal HTML/CSS/JS app with drag-and-drop upload, expiration picker, settings panel for auth token, and file list for a given token.
- Backend (`functions/api/`) uses Pages Functions file-based routing. R2 objects store `customMetadata { filename, expires, authToken }`.
- File keys are in `namespace/code` format (e.g. `8472/Ab3xY9`) where namespace is derived from the auth token hash.
- No update/modify API currently exists. Users who share a link cannot change the file content or expiration without re-uploading.
- No API docs or README exist beyond the minimal CLAUDE.md.

## Assumptions

- The existing API response contract (JSON shape, URL construction) must be preserved so any existing bookmarked links continue working.
- The update API requires the same `authToken` that was used during upload — this is the only authorization mechanism available (no database, no sessions).
- The update endpoint will accept the file key (`namespace/code`) as a body parameter rather than a URL parameter to avoid Pages routing issues with slashes in dynamic segments.
- Swagger UI will be served client-side via CDN link (no npm install) since this is a static Pages deployment.
- No R2 object-level versioning or history is needed — update simply overwrites the existing object.

## Acceptance Criteria

- **AC-1: Redesigned dark tech-style frontend with all existing functionality preserved**
  - `public/index.html`, `public/style.css`, `public/script.js` completely rewritten.
  - Dark background (`#0a0a0f` / `#111` range), cyan/neon-green accent palette, monospace or system-ui hybrid font, subtle glow effects on interactive elements, glassmorphism or gradient card treatments.
  - All existing features retained: drag-and-drop upload area, file size validation (25 MB), expiration select (1h/6h/24h/3d/7d/Never), auth token settings panel, file listing by token, copy-link button.
  - Upload result section displays the shareable link with a one-click copy button.
  - `public/expired.html` redesigned to match the new dark theme.
  - Responsive layout (mobile-friendly).
  - Loading/error/empty states for upload and file list: spinner or skeleton while uploading, inline error banners, empty-state messaging when no files exist.
  - Verification: `npx wrangler pages dev` — upload a file with and without token, verify all features work in the dark UI; resize browser to verify mobile layout.

- **AC-2: New `PUT /api/files/update` endpoint for token-authenticated file updates**
  - Create `functions/api/files/update.js`.
  - Accepts `PUT` method only; returns 405 for other methods.
  - Expects `multipart/form-data` body with fields: `fileKey` (required, the R2 key like `8472/Ab3xY9`), `authToken` (required, must match the object's stored `authToken`), optional `file` (new binary), optional `expiresIn` (seconds or empty string for permanent).
  - Validates `fileKey` existence via `bucket.head(fileKey)`. Returns 404 if not found.
  - Reads object's `customMetadata.authToken`. If absent or mismatched with provided `authToken`, returns 403 Forbidden with `{"error": "Invalid or missing auth token"}`.
  - If a new `file` is provided: validates size ≤ 25 MB (413 if exceeded), replaces object body with new `file.arrayBuffer()`, preserves existing `customMetadata` keys but merges/overwrites `filename` from the new file's `name`.
  - If `expiresIn` is provided: recalculates `expiresAt`, updates `customMetadata.expires`. If `expiresIn` is empty string, removes the `expires` metadata key (makes permanent).
  - Returns JSON with updated `url`, `id`, and optionally `expiresAt`.
  - Verification: upload a file with token `foo`, then `PUT /api/files/update` with same `fileKey` and `authToken` → succeeds. With wrong token → 403. With non-existent key → 404.

- **AC-3: Frontend "Update File" UI integrated into the file list**
  - In `public/script.js`, each file row in the file list gains an "Update" button.
  - Clicking "Update" expands an inline form below that file row containing:
    - A drag-and-drop area to select a replacement file (optional — if skipped, only expiration changes).
    - An expiration dropdown pre-populated with the file's current expiration.
    - An "Apply Update" button.
  - Sends `PUT /api/files/update` with `fileKey`, `authToken`, optional new file, optional `expiresIn`.
  - Shows success/error inline in the row; refreshes the file list on success.

- **AC-4: Swagger/OpenAPI documentation page**
  - Create `public/spec/openapi.yaml` describing all endpoints:
    - `POST /api/upload` — upload file
    - `GET /{namespace}/{code}` — download file
    - `GET /api/files` — list files by token
    - `GET /api/files/{id}` — download by old UUID (backward compat)
    - `PUT /api/files/update` — update file (new)
  - Create `public/docs.html` that loads Swagger UI from CDN and fetches the spec from `/spec/openapi.yaml`.
  - Each endpoint documented with: summary, parameters, request body schema, response codes, and example responses.

- **AC-5: Project README.md**
  - Create `README.md` at project root with: project description, feature list, prerequisites, setup steps, configuration, available commands, API overview table, deployment instructions, link to Swagger docs.

## Implementation Notes

### Sequencing (ordered batches)

**Batch 1 — Redesigned Frontend (AC-1 + AC-3 together):**
- Rewrite `public/index.html` with dark tech-style markup.
- Rewrite `public/style.css`: CSS variables for dark theme (`--bg: #0a0a0f`, `--surface: #13131a`, `--accent: #00f0ff`, `--text: #e0e0e0`), neon glow via `box-shadow`, glassmorphism for cards, smooth transitions, mobile breakpoint at 600px.
- Rewrite `public/script.js`: keep all existing upload/list/copy logic, add update-UI handlers (inline expandable form per file row, loading spinners, error banners, empty states).
- Rewrite `public/expired.html` to match the dark theme.

**Batch 2 — Update API (AC-2):**
- Create `functions/api/files/update.js`.
- Logic: parse multipart body, validate `fileKey`, `head()` the object, compare `authToken`, merge metadata updates, `put()` the replacement, return JSON.

**Batch 3 — API Docs + README (AC-4 + AC-5):**
- Create `public/spec/openapi.yaml` — OpenAPI 3.0 spec covering all 5 endpoints.
- Create `public/docs.html` — minimal HTML loading Swagger UI CDN assets.
- Create `README.md` at project root.

### Key technical decisions

- **No dependencies added to `package.json`** — Swagger UI loaded from CDN. Update API uses only Pages Functions runtime.
- **Update auth check**: The `authToken` in the update request must === `customMetadata.authToken` on the R2 object. Simple shared-secret model consistent with existing file listing.
- **Design palette**: VS Code dark theme / cyberpunk terminal aesthetic. Accent `#00f0ff` (cyan) for interactive elements, `#00ff88` (neon green) for success. Background `#0a0a0f` with subtle grid pattern (`radial-gradient`). Cards with `background: rgba(255,255,255,0.03)` and `border: 1px solid rgba(255,255,255,0.06)`.
- **Update UI**: Inline expandable form per file row (no modal library). Each row gets a `.file-update-form` div toggled with `.hidden`.

### Risk controls

- Test each batch with `wrangler pages dev` before moving to the next.
- Update endpoint must NOT allow overwriting a file's `authToken` — token is read-only after initial upload.
- `/spec/` directory must be under `public/` for static serving.

## Out of Scope

- User registration, login, or session management.
- File deletion API (no `DELETE` endpoint — files auto-expire or require manual R2 management).
- Database or KV store dependency.
- Rate limiting or upload quotas.
- File migration from old UUID key format to new namespace/code format.
- Automated unit or integration tests.
